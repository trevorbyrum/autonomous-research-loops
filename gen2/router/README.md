# Gen-2 router — the sole writer (task 1b)

`service.Router` is the one implementation of the `ControlBackend` protocol (`gen2/core/control.py`). Task 1c's lifecycle operations (cancellation, reconciliation, status and the evidence they bind) are in `lifecycle.py` (an explicit collaborator the Router composes, task 2q-b6, as below); task 1d's are in `amendments.py` (brief and contract versions, and G-1 amendment impact; an explicit collaborator the Router composes, task 2q-b8, as below) and `scheduling.py` (re-queues, reservations, the signal queue; an explicit collaborator, task 2q-b7, as below), and in `registries.py` (config bundles, the question registry, qualification records); task 1e's status read and health probe are in `status.py`, and its brief closure in `amendments.py`; task 1f's record of a capability probe is in `capabilities.py` (these three are not mixins but explicit collaborators the Router composes, through a protocol each declares of the core: tasks 2q-b2 and 2q-b3, BOUNDARIES.md "Router composition"; `lifecycle.py` is the fourth, `scheduling.py` the fifth and `amendments.py` the sixth, the last mixin: the Router inherits none; `evidence_writer.py` is the seventh, task 2q-b10: the rows of a commit's evidence and governance sections, which the Router's `_write_evidence` delegates to); task 2a's workflow write paths are spread over the modules they belong with (below). It is the only module that writes the store: only it may import `gen2.store` (`gen2/boundaries.toml`, rule 2), and only it may reach the store's write primitives (rule 9, `store_writers`). It makes no model call, spawns nothing and opens no network connection (it is granted none of those capabilities). `boundary.py` holds the checks that need no transaction. `schemas.py` validates documents against `gen2/schema/`.

Every operation follows one shape:
1. The request is normalized to its RFC 8785 form, which refuses what C-13 refuses. It is validated against its schema, including timestamps as real instants.
2. With no transaction open, the router reads staged bytes and re-hashes them. It runs the hash-truth and A10 checks.
3. One short transaction fences against current state and writes. The clock is read inside it, once `BEGIN IMMEDIATE` has returned, so every lease, deadline and expiry is judged at the time the write lock is held: time spent waiting for the lock counts (Astra 1b review A1). A lease or deadline at instant E is over at E. A write the DDL refuses rolls the whole transaction back and is reported as a refusal. Nothing is retried.
4. The reply is returned after the transaction commits.

Authority is the capability the router minted at claim. The invocation's kind, topic, pins and lease are read from its row, never from the request. A request carrying a role, actor or authority field fails its schema.

**G-1 amendment impact** (`amendments.py`). Compatibility is structural and conservative, by section of Contract v2, each class taken from the governing design (the module docstring cites it section by section; `test_router_amendments.py` DESIGN_ORACLE is the independent oracle): a change of the *framing* — the decision record, the facet map's analytic framework, facets as defined, coverage question types and what is deliberately out, or the framing version — is `reframed`; a change of the *protocol* — protocol revision, eligibility protocol, stopping profiles, applicability rules, or an obligation both revisions share (importance aside) — or a withdrawal from the *approved inventory* is `protocol_changed` (Astra 1d-repair review finding 1): an obligation the new revision no longer carries, removed or issued again under another id; a coverage cell it does not keep in scope, covered at least as it was (dropped, emptied of an obligation, put deliberately out, a deliberately-out one brought back, or otherwise changed); a cell it adds deliberately out, or as a gap beside one already listed. That fences everything pinned to the superseded revision: a conservative revision-wide fence, which the review rules sufficient at Phase 1's scope. Only additions (an obligation added, a gap filled, an obligation added to a covered cell, a cell listed in scope for a pair not listed before), importance ratings, surveillance policy and method design are `compatible`; the rule is not symmetric, an addition's revert being a withdrawal. Labels and content both count. A brief version is `lineage_only` against its successor if they differ in lineage alone, else `content_changed`. **Labels name content** (Astra 1d review finding 1): `propose_amendment` refuses a changed framing or protocol under the approved revision's label, a new label for an unchanged one, and any label not above every one the topic has recorded — so a label never names two contents and never returns. An approval that supersedes a version records an `amendment_impacts` row in its own transaction: admitted work pinned to a superseded version completes under its pins if compatible, and is otherwise fenced — its cancellation requested by the router where it can still be, its commit refused as `amendment_pending` and its result retained (C-10); screening labels, claims, verifications and coverage under the superseded revision (and those it had left compatible) with their dispositions; reopened exclusions; dossiers no longer current (G-8); reservations bound to it, closed (G-5); export generations before it. The record also keeps each earlier version's **standing** — its class against the new current version, for every version that still stood. Pins are judged by those records, not by comparing documents again: at commit, `amendment_pending` is exactly the case where a recorded impact classed the pinned version incompatible — at any approval since, not only the latest, so a later revision whose content matches a stale one again revives nothing — or where no impact lists it (`unrecorded`, fail closed), or where the pinned brief's lineage is no longer the topic's confirmed one. A claim produced under an incompatibly superseded revision is not promoted (`amendment_pending`); contract-admitted work adopts it as a new revision of its own production (V-10). Nothing listed is rewritten or deleted.

**Hold windows** are the pinned bundle's `hold_window_s` seconds, fractions included: a deadline is its creation instant plus the window in exact nanoseconds (`lifecycle._after`), a finer fraction rounding up so a positive window is never zero. **A refused bundle's failure** is recovered from by the next activation that succeeds, a replay of the active bundle included (a restart that mounts the valid bundle again), or by a start with nothing mounted restoring the active bundle (`restore_config_bundle`, the composition root's; Astra 1d-repair review finding 2): the capability fact records the recovery once, the failure kept as history.


The export outbox is committed through `commit_outcome` (outcome section `exports`), not a separate operation. The store requires every outbox row to name the operation receipt that committed it (`outbox_events.committed_by_operation_id`), and every receipt is fenced by a live lease. Before a manifest is written it is validated against `export-manifest/2`. Each extension connector must be admitted by the extension registry. Its bundle must be staged with the commit, in canonical form, valid `export-bundle/1`, and the one the manifest names.

## Boundary checks the store leaves to the router (store README)

Enforced now:
- **Schema validation** of every document the router accepts or emits: envelope, outcome document, verification and decision receipts, export manifests and bundles, delivery receipts, and its own receipts and responses. Commands (claim, transition, observation, operator decision) are checked against router-private schemas built on the shared vocabulary.
- **Hash truth**:
  - payload and result-ref digests against the staged bytes, sizes included;
  - canonical bytes and export bundles staged under their hashes; a raw decision response's digest is its artifact reference's hash, and that reference is bound like every other (below);
  - a DecisionSpec's hash recomputed from its stored document;
  - a contract revision's or intake brief's content hash recomputed before it is approved or confirmed;
  - request fingerprints and manifest hashes computed here, never taken from a caller;
  - a search observation's request identity recomputed as the hash of its request (H-5).
- **Timestamps** as real instants (schema `date-time` via `gen2/core/instants.py`), compared as instants (`utc_instant_ns`) for expiry and deadlines.
- **A10 comparisons**:
  - an observed result set's `result_count` is exactly the retrieval events captured with it. An unobserved set carries neither events nor a count. Partial stays partial, and unknown is never zero.
  - how pagination ended or continued (`page_outcome`, `continuation`; Gate D #3; the admission contract, task 2b-repair-13d) is consistent with what was read and carries what an end needs, in `boundary.check_page_outcome` (the store's CHECKs say the same, and `gen2/tests/test_admission.py` holds the two equal case by case):
    - a page nothing could be read from is `failed`, and only such a page is; a cursor belongs to a `continuation` or a `limit_reached` and to nothing else, and only from a page that was read; a partial page, a lane never searched and a lane restating an end it reported earlier never report an end (`exhausted`);
    - **the request discriminator:** the observation's request names its type (`request.request.request_type`) from the closed set find/resolve/enrich/fetch/data, and only a `find` (which pages) can be `exhausted`, a `continuation` or a `limit_reached`; every other type says `end_unknown` (or `failed`), which for it means "does not page" where for a find it means "paged, end not known";
    - **the capture acknowledgement:** a page read `complete`, and so every `exhausted` end, names the gateway's durable row of its request (`gateway_call_ref`); an answer the gateway did not capture is at most a partial lower bound (RG-4, E-2);
    - **the cursor domain:** an integer from 0 to 2^53-1, or a string of 1..8000 characters, none of them NUL, other than the finished-lane sentinel `exhausted` (`gen2/core/pagination.py`, the one definition the client also reads a `next` by).
  - a screening assessment's criteria are its pinned protocol version's, each decided no earlier than its stage. An exclusion rests on a criterion not met; an inclusion has none not met.
  - a provider-written assessment is exactly its qualified receipt's committed answer, about that work, under a spec whose protocol context is the committing invocation's admission: its topic, its contract revision, that revision's content hash, and the eligibility protocol version (Astra 1b review A3). Qualification is authority for one spec, not for that spec under another contract.
  - payload digests against staged bytes, read under the invocation's topic (the spool is topic-scoped), and every staged artifact's media type against the spool's own record of it (1c).
  - every artifact reference an outcome document embeds (a claim's text, a decision's raw response, canonical bytes) by one rule: staged with the commit or already recorded **for the committing invocation's topic**, with that artifact's size and media type — the declaration staged with the commit, its size checked against the bytes, or the recorded row (Astra 1b review A4). Two references to one hash in a commit must agree. An artifact row is the physical record of its bytes, shared by every topic that staged them; a topic may reference it only through its own `artifact_topics` row, which the router writes when that topic's commit or evidence records bytes staged in its spool — content identity is not topic authorization (Astra 1c review A6, Q6 ruling). An export bundle's own artifact references are bundle content, assembled in Phase 3; the router checks the bundle's schema, not what they name.

- **Registries** (1d): a decision commits only under a stored spec whose pinned question (id, version, hash) the committing invocation's pinned bundle carries; qualified authority rests on a live qualification record of exactly the receipt's provider, class and spec, checked at validation and again under the commit's write lock (a revocation between the two is seen), with the DDL as a third layer.

### What an observation command is trusted for

*A reading of the design, stated for review (task 2b-repair-13d; Astra R13B-2; corrected in 2b-repair-14 for Gate D #2 F6), not a stronger guarantee than it is.* The design makes **trusted station/gateway code the capture boundary**: flow S4 step 2 ("the station/gateway captures retrieved candidate identities at retrieval time (before any screening) … the router persists these events and evidence accounting aggregates them"); BOUNDARIES' station supervisor is trusted code that must never trust *agent* self-report and is checked by state-integrity audit sampling; and the flow's S5 state integrity has "an independent agent re-derive sampled state entries from raw ledgers and diff". D-1's raw-response retention is the *decision receipts'* (the decision layer's), not a retrieval-response replay system: nothing in D-1 retains the gateway's reply to a retrieval. `record_observation` is therefore a command from that trusted code (the invocation's capability; no endpoint exposes it to an agent), and the router **persists** what it reports. It never sees the gateway's reply and does not re-derive the observation from it.

- **The router and the store enforce:** coherence (the request identity is the hash of the request; a count is the events captured with it; the `page_outcome`/`continuation`/coverage relations above), the capture acknowledgement, the request discriminator and the cursor domain — each for every admitted observation, through any path that reaches the table (the CHECKs are the same rules).
- **They do not enforce that a captured outcome is truthful: a coherent false claim by trusted station code is outside router semantic enforcement.** A well-formed command that relabels what the gateway's reply implied — `limit_reached` with its cursor recorded as `exhausted` with none, on a `find` whose call reference is real — is admitted on its first write; an honest command for the same observation afterwards conflicts (`observation_id_conflict`) rather than correcting it. Sampled independent re-derivation can detect it when retained evidence supports that check, and missing required evidence is itself an audit failure. `gateway_call_ref` acknowledges a durable *call row* of the gateway (the request, its correlation and telemetry), not a response artifact and not proof of the asserted end: the call row holds no response bytes or digest, so today it locates the request and is not evidence of what the gateway answered (it is why a page read whole must carry one). The audit is not built by this task (BUILD-STATE: bounded audits, "sampled state re-derivation", task 2e2), and **2e2 must give the retrieval audit an independently checkable evidence requirement before real workflow acceptance** (recorded in BUILD-STATE). The router does not become a second gateway implementation to close it. `test_admission.TheTrustModel` records the admitted relabelling as a test, so it is not mistaken for a guarantee.
- **Stores written before this change** are still refused at open (the schema differs; no migration or backfill exists), and a later reconciliation must preserve old counts and identities and mark unrecoverable end knowledge unknown, never exhausted.

Deferred, each with its phase:
- A DecisionSpec's rubric and input-builder versions against a registry: Phase 3, with live question content (no live call precedes an immutable, retrievable question and input-builder version).
- Qualification records are Phase 1 fakes; immutable evaluations, population provenance and the qualification-change audit are Phase 3.
- Verification-receipt spans against the quote check's offsets, and the obtained tier against what the acquisition route can deliver: Phase 2, with quote capture and tier-0. Until then no router path records a quote check, so a receipt can name only one already stored (the store's key).
- A dossier's content hash against its document: Phase 2, where dossiers are assembled.

## Structural limits

- **Task 1d.** The compatibility rule is structural: an edit harmless in meaning is still incompatible (fenced), and the rule never calls compatible an edit that changes framing or protocol text. A stale version's authority returns only through new work (adoption, re-screening, a re-queue); Phase 1 has no reconciliation record that restores it. A revision written around the router (only fixtures do) is classed by its content; the label binding is checked where the router writes an amendment. A lane's re-queue binds the lanes whose last work failed or was cancelled: the router cannot tell fresh work of a lane whose last work ended well from a retry, so the retry budget is the budget of the path through failed and cancelled work. Budgets, windows and cooldowns are judged on the router's clock read under the lock; the signal queue's window counts reviews by their opening time. Config bundles are activated by the trusted surface; the router validates and records what it is handed, and a mounted file's truth (that it is what the operator mounted) is deployment's.

- **The capability is a bearer identifier, held in process.** A capability is unguessable and router-minted, but nothing authenticates the process presenting it; an unguessable identifier does not by itself authenticate anyone. Since task 1e, what crosses a process boundary is authenticated: the engine's listener takes an operator's or the exporter's bearer token, authorizes each command by the principal's role, and names the principal in what the router records (`gen2/operator/README.md`). The capability-bearing calls (claim and everything under a capability) are not on that listener: the supervisor makes them in the engine's own process, and no agent is handed a capability (its environment is the order's own, `gen2/supervisor/jobshim.py`). The router still trusts what the surface hands it — a decision's `operator_id`, a closure's `closed_by` — to be the authenticated principal; it does not check a name against a principal set. No agent code runs with access to the Store, the database file or another invocation's capability; that it cannot reach them is the process and filesystem boundary's, which is deployment's.
- **Rule 9 is architectural lint, not runtime isolation.** It rejects a direct import of a store write primitive, an import alias of one, and a module-attribute chain it can resolve statically (`gen2.store.api.Store.insert`). It does not see ordinary re-export and alias chains, which need no reflection:
  - `from gen2.router import service` then `service.api.open_store(...)`: a module the router imports, reached through the router's namespace;
  - `forward = service.api` then `forward.open_store(...)`: an assignment alias of that re-export;
  - `getattr(service.api, "open_store")(...)`;
  - a function that receives a Store and calls `store.insert(...)`;
  - the router's private `_store` reached by reflection.

  What backs it is the import graph, review of the composition root and of where Store handles flow, an API that hands no Store to ordinary clients (a Router owns its Store and returns plain values), the DDL's own consistency checks (which do not establish who the caller is), and the process and filesystem access boundary, which is not demonstrated yet (1e and deployment). Only the composition root constructs a Router.
- **Interleavings are chosen, not exhaustive.** The lock-wait tests hold the write lock on one connection while a second router waits for it and its lease or deadline passes; the insertion-race test commits another topic's artifact between this commit's validation and its transaction. Each is one schedule, chosen to cross its boundary, with threads in one process. None proves arbitrary concurrency.
- **Faults are in-process.** They are exceptions at named points, plus an `os._exit` of a child process inside the transaction on a durable store. Neither simulates power loss or a crash inside SQLite's own commit.
- **The validator covers exactly the keywords `gen2/schema/` uses.** It refuses to load any other keyword. Agreement with `jsonschema` is shown on the committed fixtures and their single-point mutations, not on every possible input.
