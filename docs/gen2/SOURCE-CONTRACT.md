## What this is, and the rulings behind it

The architecture metrics (`tools/gen2_metrics.py`) are **exact over a declared, guarded supported-source subset** of Python, not over arbitrary Python (Gate D #4 option B). A source form outside the subset is **refused with an actionable diagnostic before anything is measured, recorded or certified** (a `report` or `hotspots` run is the one exception that writes anything: it writes PARTIAL tables for what could be read, marks the input incomplete, non-passing and not certified, and writes `NOT-CERTIFIED.txt` beside them; it never certifies). The refusal stage runs first in every command that reads the production source — the metrics `check`, `report`, `admit`, `rebaseline` and its bootstrap, the history `hotspots` report, and the locator check — however the command is run. It is **unwaivable**: no exemption, no numeric budget, no identity transition and no ledger entry excuses it. The cure for a refusal is to change the source (or, through an amendment below, the contract), never to classify it.

The operator's rulings of 2026-10-05, each given as "I agree" to the three recommendations of Gate D #4:

1. **Option B is adopted.** The metrics are computed exactly over this guarded subset. An unwaivable source-refusal stage precedes measurement. The repair-2 brief's permission to pass analysis by classifying an unresolved binding in the ledger (`classify` entries, the `unresolved_base` metric) is **withdrawn**; the claims and tests that relied on it are amended (see "Amended" below).
2. **The minimal production change is authorized before 2q-a acceptance.** `_no_reading` (`gateway/research_gateway/core/payload.py`) and its two uses, `Sealed` and `Passive`, are replaced by explicit, statically represented methods that share one refusal implementation; behaviour is unchanged.
3. **Sequencing.** That production change belongs to the same repair and the 2q-a family review history; it is not a separate 2q-b slice.

"Exact" means exact relative to the metric definitions in `tools/gen2_metrics.py`. The import graph counts explicit import syntax (including local and `TYPE_CHECKING` imports); it is not the runtime dependency graph. Complexity measures authored function bodies with the published AST proxies; it is not a semantic-equivalence judgment. Collaboration measures direct `self` calls between the classes of one inheritance family, attributed by C3 order; it is not a call graph. Low metric values do not establish scientific validity or software correctness. **Under version 2 "exact" is claimed for the supported forms only** ("Version 2: soundy by declaration"): a form the contract refuses is not measured, and a form it names as outside its claim ("What the contract does not claim") is measured as written, with no assurance that nothing else changes it at run time.

## Version 2: soundy by declaration

**The guarantee.** Version 2 claims this and nothing more: **the metrics are exact for the supported forms (the rows below); the named dynamic mechanisms are refused wherever they appear in production code; nothing else is claimed.** A form the contract supports is measured exactly. A mechanism it names is refused before anything is measured (see "Dynamic mechanisms"). Everything else is outside the claim, and "What the contract does not claim" lists it. This replaces version 1's attempt to follow values: version 1's recognised producers of a namespace (`type(x)`, `globals()`, `locals()`, `vars(x)`, `getattr(x, ...)`, the methods of a namespace's dictionary) and its classification of what a call, a container's element, a loop target or a conditional hands out are gone, and so is version 1's open item about what an unrecognised call hands out. The contract no longer says what such a value is, and does not claim to.

**The precedent** (the research note `docs/gen2/research/2q-a-round-cap-20261005.md`). No realistic static analyser of a dynamic language is sound; the accepted standard is to be *soundy*: handle most language features soundly, and deliberately and *explicitly* under-approximate a small named set of hard dynamic features (reflection, `eval`, runtime namespace mutation). That is the position of Livshits, Sridharan, Smaragdakis, Lhoták, Amaral, Chang, Guyer, Khedker, Møller and Vardoulakis, "In Defense of Soundiness: A Manifesto" (Communications of the ACM 58(2), 2015). The state of the art for Python is precise but incomplete: PyCG (Salis et al., ICSE 2021, arXiv 2103.00587) reaches about 99.2% precision and about 69.9% recall on real projects and deliberately does not resolve dynamic constructs; the architecture linters in production use, import-linter and grimp, check explicit import statements only, and dynamic imports are out of scope by design. Version 2 is the same position, written down: the contract names what it does not see, and refuses the mechanisms that would let production code change a namespace where it cannot see it.

## Dynamic mechanisms

**The ban (`SRC-DYNAMIC-MECHANISM`).** A *reference* to any of these names is refused anywhere in production code, in either service, whether it is called, aliased, passed, stored, imported or reached as an attribute. It is a ban on the reference and not a tracking of values: aliasing a banned name (`put = setattr`) is itself a reference, and no value that one of these mechanisms produced is followed.

| Family | Names |
|---|---|
| reflective writes | `setattr`, `delattr`, `vars`, `globals`, `locals` |
| namespace access | any `__dict__` access; `sys.modules` (the attribute `modules`, `from sys import modules`) |
| dynamic import | `importlib` (the module, any `importlib.*` import, and `import_module`), `__import__` |
| code execution | `exec`, `eval`, `compile` (the built-in; `re.compile` is another name and is not banned) |
| attribute-protocol writes | `__setattr__`, `__delattr__` and `__getattribute__`, assigned, called or reached as an attribute |
| three-argument `type` | `type(...)` with other than one plain positional argument (a starred call, a keyword, two or three arguments), by its name or by an alias, is a class made by a call (`SRC-CLASS-DYNAMIC`) |

A reference is recognised by its syntax: a name in any context, an attribute, an import (`import importlib`, `from importlib import x`, an `as` alias that is a banned name), and an attribute of an imported `builtins` (or of `__builtins__`) that names one of the built-ins above. The attribute `modules` is refused whatever it is an attribute of, so that `sys.modules` cannot be reached through an alias of `sys` or a call that returns it. A `def` or `class` of a banned name (`def __setattr__` in `_Unread`, which refuses every write) is a **definition and no reference**, so it is not banned; a hook the class defines (`__getattribute__`) is the class-hook refusal of version 1, which stays.

**What the ban does not see (declared).** A string that names a mechanism (`getattr(obj, "__dict__")`, `__builtins__["eval"]`), and a banned callable that reaches the code as an argument or a return value from a place the ban does not read. The ban refuses the *spelling*, in production code. A banned name in tests and tools is not this contract's concern.

**The loader.** `importlib` and `import_module` are referenced at the one inventoried loader site, and only there: the two statements the next section lists. The loader's own checks ("Dynamic loader inventory": the call, the discovery, the filter, the file inventory and the implementation fingerprint) still apply to it, and the calls it lists as loaders (`exec`, `eval`, `compile`, `__import__`, `importlib.reload`, `runpy.run_path`, `pkgutil.iter_modules`, ...) are still refused as uninventoried loads (`SRC-LOADER-UNINVENTORIED`) where the ban applies too.

## Excepted statements

Each exception is recorded by **file, enclosing function and the exact normalised statement** (`ast.unparse` of the statement that holds the reference), with its reason. It matches only that statement in that function: the same statement in another function or another file, a changed statement, and a second copy of it in the same function are all refused, and any other use of a banned name anywhere is refused. **Adding an exception is a contract amendment** (the operator rules on it; this document and `EXCEPTIONS` in `tools/gen2_source_contract.py` change together and the version number rises).

| File | Function | Statement | Names | Reason |
|---|---|---|---|---|
| `gateway/research_gateway/adapters/__init__.py` | (module) | `import importlib` | `importlib` | the import of the one inventoried dynamic loader; the loader's fingerprint pins this statement |
| `gateway/research_gateway/adapters/__init__.py` | `load_all` | `mod = importlib.import_module(f'{__name__}.{info.name}')` | `importlib`, `import_module` | the one inventoried dynamic import: adapter discovery over the package's own path, with a pinned filter, file inventory and implementation |
| `gen2/supervisor/jobs.py` | `Job.hold` | `key, held = ((stat.st_dev, stat.st_ino), _HELD.__dict__.setdefault('keys', set()))` | `__dict__` | `_HELD` is a `threading.local()`: its `__dict__` is that one thread's own data, the journal locks the thread holds, and no class's or module's namespace |
| `gateway/research_gateway/core/payload.py` | `Sealed.__init__` | `object.__setattr__(self, '_value', value)` | `__setattr__` | instance-slot initialisation behind a `__setattr__` that refuses every write (`_Unread`): a plain assignment would be refused by the class itself |
| `gateway/research_gateway/core/payload.py` | `Passive.__init__` | `object.__setattr__(self, '_value', value)` | `__setattr__` | instance-slot initialisation behind a `__setattr__` that refuses every write (`_Unread`), as in `Sealed`: a plain assignment would be refused by the class itself |

The two payload statements write the instance attribute `_value` of the receiver; the contract checks that write like any other write through the receiver: `_value` must not be a method of the class family (`SRC-ATTR-OVERRIDE`). The loader's two statements are also the loader's: changing either changes the loader's fingerprint.

## Private names

**A private (name-mangled) identifier is refused (`SRC-PRIVATE-NAME`)**: any `__name` that does not end in two underscores, used as a name, an attribute, the name of a `def` or `class`, a parameter, an import alias or an import's module path, a name in `global` or `nonlocal`, an `except ... as` or match capture, a keyword of a call, a class or a class pattern, or an entry of `__slots__`, in any context (the compiler does not mangle every one of these, a call's keyword among them; version 2 does not distinguish: no identifier in production code starts with two underscores and does not end with two). Python holds such a name in a class body as `_Class__name`, and the metrics' facts would have to spell it as the compiler does everywhere a name is read, written or looked up as a member; Astra's 2q-a-repair-6b review (R6B-1, R6B-2) found that two consumers spell it two ways. Version 2 removes the form instead of modelling it: the refusal comes before any fact is used, so no fact is produced from a mangled name. An ordinary dunder (`__init__`, `__eq__`, `__hash__`) ends in two underscores and is not private. The index still spells names as the compiler does (`mangle`, "Binding identity"); that is defence in depth, and no accepted source reaches it.

## Quoted class-body annotations

**A quoted annotation of a statement in a class body is refused (`SRC-QUOTED-ANNOTATION`)**: `f: "ClassVar[object]"` and the like. The `dataclasses` decorator reads a *string* annotation by its text (a regular expression on the name, looked up in the module's namespace), not by what the name is bound to, so a quoted `ClassVar`, `InitVar` or `KW_ONLY` can hide an instance field that the generated `__init__` writes; the contract cannot say what the string names. Other quoted annotations (a method's parameter or return annotation, a name inside a subscript such as `Optional["A"]`) are not dataclass field markers and are not restricted.

## Closure: positive recognition

The guard does not refuse a list of known-bad spellings and trust the rest (task 2q-a-repair-3 did, and each review found another spelling). It is **closed**: every construct that can
**bind or rebind a name** in a module or class namespace, or **change an attribute or member** of a measured module or class, has to be one of a finite, enumerated set of recognised
forms whose effect the index records, and **anything else is refused (`SRC-FORM-UNRECOGNISED`)**, in whichever structural position it appears: statements, expressions inside function
headers and annotations, defaults, decorators, class bodies, comprehensions, loop targets, `global` and `nonlocal` redirection, imports, walrus expressions, and attribute or subscript
stores on imported modules or classes. This is part of version 1's enforcement and not a scope change: the recognised set is exactly the supported rows below, and a new form gets in
only by a contract amendment, never by the tool's default. The enforcement is structural, one dispatcher over each kind of site, in which a kind with no entry is a refusal:

| Dispatcher | What it recognises | An unrecognised kind is |
|---|---|---|
| The walker's table of syntax forms (`FORMS` in `tools/gen2_source_index.py`) | Every syntax node class that can occur in the supported subset, each with the handler that records what it does to a namespace: a binding, a store, a call, a new scope (a class, function, lambda or comprehension) or nothing. The walk is by node, so no position is skipped. The `type` statement and type parameters are not recorded. | a node class with no entry, and a name written where no statement says how |
| The binding kinds of a class body (`Contract.CLASS_FORMS`) | `def`, `class`, assignment, augmented assignment, loop and `with` target, walrus, `del`, import, and an annotation alone; each is checked by name against the hook names, the names of the class family's methods and the methods the body itself defines | any other kind of binding |
| The binding roles of every scope (`BINDING_ROLES`) | the fourteen roles the index records | a role the contract does not list |
| The store bases (`Contract.STORE_FORMS`) | a write through the method's own receiver (an instance attribute: it must not be a method of the class family), through data (a parameter, a local or module-level value, an element of a container, the result of a call: **not followed**, see "What the contract does not claim"), provided the attribute written is not the name of a method of a class family of more than one class (the object may be an instance of it: `SRC-ATTR-OVERRIDE`) | a write through a class (a class name, an alias of one, `type(x)`, `x.__class__`), a module, a package, a function or an external object, which the resolver names, and a write through something nothing in the source says what it is |
| The call forms | class-making calls (`type` with other than one plain argument, `types.new_class`) and the loader calls | (none: other calls are calls) |
| The banned mechanisms (`BANNED`, `EXCEPTIONS`) | no reference to a name in the ban list, except in an excepted statement ("Dynamic mechanisms") | a reference to one |

A name bound once, directly, to another name or attribute chain (`loader = iter_modules`, `me = self`, and each name of a literal unpacking, `size, loader = (len, iter_modules)`) has the identity or the kind of that chain, so an alias is the thing it aliases; an alias of a name whose bindings compete (`loader = iter_modules` where `iter_modules` is imported and then rebound) is refused where its identity matters, never read as having none. One resolver decides it for every consumer ("Binding identity").

## Binding identity

Task 2q-a-repair-5 (slice 1 of the repair of Astra's 2q-a-repair-4 finding F1). Which class, function, module or external object a name is has **one** answer: `Facts.expr` in `tools/gen2_source_index.py` (`Facts.identity` is its dotted text). It follows explicit imports, aliases (a name bound once to another name or attribute chain, however the binding is written: `x = y`, `x, = (y,)`), qualified module chains and uniquely bound explicit re-exports across files, to the identity the name certainly has, or refuses with the category of the row. The consumers all ask it and none keeps a path of its own: the bases of a class (and so the metrics' families and ownership), the identity of a decorator, a loader or any other call (`pkgutil.iter_modules`, `type`), the kind of what a store is written through, a dataclass field marker, and the owner a qualified locator may descend through. A loader call that is re-exported, aliased or unpacked is the loader call, so it is refused as an uninventoried one (`SRC-LOADER-UNINVENTORIED`) wherever it is called; the names the ban lists are refused where they are referenced, first of all. A base is the one place that does not follow an assignment, because the contract refuses a base bound by one (`SRC-BASE-ALIAS`).

**Which scope a name lives in is the compiler's answer, not a rule of this tool** (task 2q-a-repair-6; Astra's 2q-a-repair-5 review F1). `locate` in `tools/gen2_source_index.py` reads the symbol tables of the standard library's `symtable` module, the compiler's own scope analysis, and nothing else decides whether a name is local, explicitly or implicitly global, nonlocal or free: a use or a write belongs to the scope itself, to the module, or (free or nonlocal) to the nearest enclosing function whose table binds it, never to a class body between. The index still records *what* a binding refers to; the table says *where* the name lives, so a `global` or `nonlocal` declaration that changes the owner of a read (`global A` in a nested function, past an `A` the enclosing function imported) changes it for every consumer. Each scope of the tree is given the compiler's table for it by following **the order in which the compiler enters scopes** (task 2q-a-repair-6b; Astra's 2q-a-repair-6 review R6-1): a comprehension's first iterable, a function's defaults, decorators and annotations and a class's decorators, bases and keywords are read where the scope is written, before its block, so a generator expression inside the first iterable of another is entered before it, and scopes that share a type, a name, a line and even their parameters are never told apart by those. Every pairing is then **proved both ways**: the names the tree writes in a scope, spelled as the compiler spells them, must all be in its table, and the table may hold nothing else but the compiler's own names (`.0`, `__class__`), the `global` names declared below in the module's table and the free names of the scopes below that it passes up. A scope with no table, a table with no scope, or any disagreement is refused (`SRC-FORM-UNRECOGNISED`: the tool and the compiler disagree, which is a defect of the tool) and so is a lambda or comprehension inside an annotation the compiler does not read. A file the compiler's symbol table itself refuses (Python's `SyntaxError`: a `nonlocal` with no enclosing binding, written or not, a `nonlocal` whose binder lies beyond an intervening function's `global`, an annotated name declared `global`, a star import below the module level) is refused with the compiler's message and line (`SRC-INV-PARSE`) and has no facts.

**A private name is the compiler's mangled one** (task 2q-a-repair-6b; R6-2). In a class body, and in every function, lambda and comprehension nested in it down to the next class, a name `__name` (no trailing `__`, no dot) is held as `_Class__name`, the class name's leading underscores stripped and nothing mangled when the class name is all underscores: the index spells every read and write that way when it asks the table (`mangle`), records the binding under the name as written, and counts `__h` and `_C__h` in class `C` as one name for the duplicate and rebinding rows (`SRC-DEF-DUPLICATE`, `SRC-DEF-REBOUND`). A binding the tree writes for a name the table does not hold is **refused**, never read as the module's (`SRC-FORM-UNRECOGNISED`). Attribute names are not symbols and are not mangled here: `self.__h` is looked up as written. **Since version 2 this is defence in depth: a private name is refused before any of it is used ("Private names", `SRC-PRIVATE-NAME`), so no accepted source reaches the rule and no fact is produced from a mangled name.**

The table is the authority except in three places, each stated here because it is not the compiler's word. (1) CPython 3.12 inlines a list, set or dict comprehension into the table of the scope that holds it (PEP 709) and does not separate its iteration variables, so a comprehension's own iteration variables are the comprehension's (the index records them) and its other names the holding scope's; a generator expression has a table of its own, and an assignment expression binds where the table puts it. (2) A name only an annotation writes in a scope, under `from __future__ import annotations`, is one the compiler never evaluates, and the table does not hold it: the module's namespace answers it. That is this contract's own policy, which the evaluation of a stored annotation by `typing.get_type_hints` resembles only where it uses the module's globals (that function may also use explicit or inferred local namespaces, and the index does not model them); it is no claim of equivalence with it. Only such a name takes this path: a name an executable binding writes is never looked up this way. A consumer that asks about a name a scope does not write at all (a base or a field marker is resolved in the scope that holds the class) is answered as any name a function does not bind: the nearest enclosing function whose table has it local, else the module. (3) There is no longer a place where scopes are paired by a header: see the order above.

**The correspondence is validated for the reference interpreter only.** The order of scopes, the table's names and the mangling were read from, and checked against, CPython 3.12.3 (`symtable`); the index runs under the interpreter the tools run under and has been shown to agree with the compiler's tables for that version alone. Another interpreter version is not qualified until the pairing, the order and the supported syntax are validated for it (the validation refuses the file where they differ, which is the safe failure, but is not a claim that they agree).

Two rules decide what the resolver reads beyond scope. An assignment of a literal tuple or list to a literal tuple or list of the same length, without a starred element, binds each name to the value at its position; any other unpacking binds its names to elements of one value, which no resolver can follow. A `nonlocal` write is recorded in the function the compiler's table says binds the name (a parameter, an assignment, an import, a definition ...), whatever the textual order of the binding and the nested function. The rebinding of an imported name or a definition from a nested function is then the same refusal as any other rebinding (`SRC-DEF-REBOUND`, `SRC-BINDING-COMPETING` where the name is used as a base).

**An alias the resolver cannot follow is refused, not accepted.** When an ordinary alias (`loader = iter_modules`) names something whose bindings compete and include an identity (an import, a definition, a class or another alias), or is an alias of itself, the resolver returns an explicit unresolved result marked as an alias, and every consumer refuses on it: a decorator or a base through the refusals of its own row, and a call through it, the identity of a store's base or of a loader call or a `type` call, and a dataclass field marker as `SRC-BINDING-COMPETING`, naming the line. An alias of a name whose competing bindings are all data (a parameter that is reassigned) carries no identity the contract knows, and is no refusal. This enforces the rows below; it does not decide what the alias captured.

**What this closes:** the recognition of an owner or a producer through an import, an alias (also one the resolver cannot follow, which is refused), a re-export, a `global` or `nonlocal` declaration (the scope is the compiler's), or a `nonlocal` rebinding. **What it does not claim** (version 2): what a call, a container or a parameter hands out at run time (a function that returns a module, a module in a list, a module passed to a helper): see "What the contract does not claim"; the mutators of a namespace's dictionary and the quoted field markers of a dataclass are refused outright ("Dynamic mechanisms", "Quoted class-body annotations"). Nothing here claims the family of binding errors is closed beyond the supported forms.

## External terminals

A base that resolves outside the production inventory is an **external terminal**: its identity is recorded as the resolved dotted name (`builtins.Exception`, `typing.Protocol`, `threading.Thread`, `urllib.request.HTTPHandler`). A class whose bases are all external is a leaf outside project collaboration: it adds no project method and takes none. Two lists of identities are modelled:

| List | Identities | Meaning |
|---|---|---|
| modelled typing forms | `typing.Generic`, `typing.Protocol` | a subscript on them is erased; they add no project method |
| mixable with a project base | `builtins.object`, `typing.Generic`, `typing.Protocol` | the only external bases a project base may share a class with |

Any other external base mixed with a project base is refused (`SRC-BASE-MIXED`): its methods could precede or follow the project's in an order the analysis does not model. The same holds through ANCESTORS, not only the immediate bases: for `A(UserDict)`, a project class `B` with a method `keys`, and `C(A, B)`, the resolution order is `C, A, UserDict, ..., B`, so `self.keys()` finds `UserDict`'s name before the project's. A class whose resolution order (C3, with `object` implicit and last) places an external class other than the modelled ones before a project class is refused, because an external class's absence of the name cannot be established. An external class after every project class cannot hide a project name, and a class whose bases are all external is a leaf outside project collaboration. An unknown external behaviour never silently resolves a project method.

## Effective members

Primary documentation: the Python data model on `object.__hash__` ("A class that overrides `__eq__()` and does not define `__hash__()` will have its `__hash__()` implicitly set to `None`") and the `dataclasses` documentation ("If eq and frozen are both true, by default `@dataclass` will generate a `__hash__()` method for you. If eq is true and frozen is false, `__hash__()` will be set to `None`"; "Neither will it add or change an existing explicitly defined `__hash__()` method"; with `frozen=True` a `__setattr__` or `__delattr__` the body defines is a `TypeError`, so such a class is never built). `gen2/tests/test_source_closure.py` proves the recorded members against the interpreter, for a plain class and the three recorded dataclass forms over six bodies each, in both services.

Ownership and attribution use a class's **effective members**: what Python has built once the body has run and the recorded transformations are applied, not only the methods the body writes
(`tools/gen2_source_contract.py` `effective`). A name is attributed to the first class in the C3 order that HAS it as an effective member; a member that is not a callable `def` (a property, a
slot, data, an implicit `None`) is data, so a call of it calls its value and nothing after it in the order is reached.

| Effective member | Where it comes from | Effect |
|---|---|---|
| a `def` | the body | its role (method, `staticmethod`, `classmethod`, property) |
| any other name bound in the body | the body | data (an annotation alone binds nothing) |
| `__hash__ = None` | **implicit**: a body that defines `__eq__` and not `__hash__` (the Python data model on `__hash__`) | data: a call of `self.__hash__()` is not attributed to an ancestor's `__hash__` |
| the names a literal `__slots__` lists | the body | slots (data); a slot named like a method of the family is refused |
| `__init__`, `__repr__`, `__eq__` | a recorded `@dataclass`, unless the body defines them | generated methods |
| `__hash__` | a recorded `@dataclass` (the `dataclasses` documentation's table, for the recorded forms only): `None` when frozen is false, a generated method when `frozen=True`, in both cases unless the body defines an explicit `__hash__` | data, or a generated method |
| `__setattr__`, `__delattr__` | a recorded `@dataclass(frozen=True)` | generated methods |
| each annotated field (not `ClassVar`, `InitVar`, `KW_ONLY`) | a recorded `@dataclass`: its generated `__init__` writes it on every instance | an instance attribute; a field named like a method of the class family is refused (`SRC-ATTR-OVERRIDE`) |

The **fingerprint** pins the reviewed implementation, not only the text the filter is written in: it is the SHA-256 of the normalised syntax (positions, comments and docstrings ignored) of the function `load_all` and of every statement of its module that is not another definition (its imports, `_SKIP`, and any rebinding of a name it reads, such as `__path__`), and any change to either is a refusal until the contract is amended, so turning a `continue` into a `pass` under the same condition is caught. ## Explicit non-graph exclusions

Unchanged from the metric definitions, and not claims of the contract: `super()` calls, `self.<attribute>.method()` calls, indirect and injected calls, reflection on data, and attribute reads are outside the import and direct-call metrics, that is, they are not COUNTED. That is not a ruling on what an indirect operation changes: whether a value that reaches a store through a call, a container or a parameter can replace the owner of a later direct call is declared outside the claim ("What the contract does not claim"). The contract constrains only the parts of Python that decide identities, bindings and attribution.

## What the contract does not claim

Version 2 makes no claim about these, and does not refuse them either; they are named so that nothing is read into silence.

- That the code is correct, or that a refactor that lowers a metric is an architectural improvement: a recognition change that moves a measurement is reported as a **measurement change**.
- That a locator's cited name is the right definition or that the prose around it is true (only that the name exists where it says, through facts the contract guarded).
- That an author's stated reason in the ledger is true (reviewed metadata under trust model B; Git records commitment, review establishes adequacy).
- **That a value never carries a module or a class to a write.** A module or a class that is returned by a function, held in a container, passed as an argument or unpacked from a call, and then written through (`def owner(): return a.A` and `del owner().f`; `box = [a]` and `box[0].A = object`; `def replace(ns): ns.A = object` called with a module; a call result written through), is **not followed**. A name the resolver can follow (an import, an alias, a re-export) is; a value is not. Such a write can change the owner of a later direct call or a qualified locator, and the contract neither detects it nor claims otherwise. Astra's 2q-a-repair-4 probes `returned-module`, `subscript-module`, `parameter-module` and `returned-class-delete` are exactly these. This is the soundy boundary of version 2: the mechanisms that write a namespace without naming it are refused, and a plain attribute write through a value is ordinary data processing.
- **Strings that name a mechanism** (`getattr(obj, "__dict__")`, `__builtins__["eval"]`): the ban reads names, not strings.
- That an external class's absence of a name can be established: every external class other than the modelled ones is assumed able to supply any name, so none may come before a project class in the resolution order.

## Amendment path

The contract changes only by an explicit amendment (version 2 is the most recent: the operator's rulings of 2026-10-05 and 2026-10-06, "Version 2: soundy by declaration"): the operator rules on the concrete form; `docs/gen2/SOURCE-CONTRACT.md` and `tools/gen2_source_contract.py` change together and the version number rises; a refusal test and a positive test accompany every new row. Finding another valid Python form outside the subset is a new refusal fixture, not an automatic extension of the analyser: a concrete counterexample **inside** the subset still blocks, and a form outside it must be refused.
