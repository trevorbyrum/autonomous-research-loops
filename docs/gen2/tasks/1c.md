## Build `gen2/supervisor/`
The single lifecycle implementation for all five kinds: research pass, discovery, delegate, verification and checkpoint.

- **Launch intent before spawn (L-2).** Record the launch intent with its stable job handle before the process is spawned.
- **Process identity (L-3).** Identity is the job handle plus host/container identity, boot identity and the process start fingerprint, never a bare PID. A crash between spawn and the identity record is resolved by idempotent job lookup, or by terminating the job and reconciling.
- **Deadlines, pause and cancellation (L-7).** Run a final launch-admission check and confirm descendant handling before releasing capacity.
- **Delegates and verifiers (L-8).** They run as supervisor-owned jobs, and submit and reconnect under the same invocation ID.
- **Protected spool (C-9).** Artifacts are staged immutable, content-addressed, topic-scoped and size-bounded. Privileged code never opens an agent-selected destination path; path traversal and symlinks are refused. The router commits references only.
- **Structural checks decide outcomes (L-5, L-9).** Agent self-reported completion is never accepted. Empty output is recorded as a structural failure in the observation stream.
- **`outcome_unknown` (L-4).** Leaving it requires a durable reconciliation record of that episode: its method and result. It is never treated as vanished, failed, retryable or done. The store already has the columns 1b deferred here; wire them.
- **Retry budgets (L-6).** Every retry path consumes a declared attempt/time budget.
- **Router outage (C-10).** Admitted work may finish within its deadline and the supervisor retains the result. On recovery, delivery goes through the router's replay.
- **Fake executors.** Deterministic, scriptable stand-ins for each kind. They can succeed, crash at any point, hang, return empty output, emit a wrong digest, claim success without output, or spawn descendants. No real models, gateway calls or network.

## Prove (release gates RG-2, RG-3)
For **every kind**, run the same fault set with whole-store assertions:
- spawn/receipt uncertainty (crash between spawn and identity record);
- primary exit with a live descendant;
- supervisor crash at each lifecycle boundary, then restart;
- router unavailable, then recovered;
- stale result after lease loss;
- replay of a delivered result;
- timeout;
- cancellation, including cancellation racing completion;
- empty output;
- `outcome_unknown` entered and then reconciled.

Each fault must end in a bounded, visible state: a typed hold or control incident, never silence. Use real child processes where the fault needs them.

## Mutation-runner gap: close it first (carried from Astra's 1b-repair-2 review)
`tools/gen2_mutations.py` swaps modules only in the current interpreter. Fresh child processes import the unmutated files from disk, so any kill that depends on a subprocess is not real. Since 1c's crash tests depend heavily on child processes, add a disk-mutation mode (or an explicit loading mechanism) that children honor. Then show that at least one subprocess-only killer is killed through it. Audit the inventory for any other kill that rests on a child.
