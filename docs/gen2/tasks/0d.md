# Task 0d — one standard export API; remove everything specific to the operator's own setup

## Operator ruling (the user, 2026-09-26). This is binding and overrides the adjudicated S8 text.
Gen-2 is going open source. **Nothing in the build may carry a feature, route, schema value, service or setting specific to the operator's own infrastructure.** External export is **one standard API that any database can connect to, local or cloud**. The operator's Neo4j/Qdrant GraphRAG gets connected to that API after the build, like anyone else's database. It is not built in, and it does not get its own path alongside the generic one. **Don't change the internal process** (S1–S7, router, store core, importer, the internal SQLite record). Only the outbound surface changes.

## What is wrong now
Neo4j/Qdrant are hardwired as "publication sinks": the `common.schema.json` `sink` enum `["neo4j","qdrant"]`, the DDL `CHECK (sink IN ('neo4j','qdrant'))` on `sink_delivery_receipts` and `sink_generations`, the publication-manifest and freshness-envelope schemas and fixtures, store tests (`test_store_ddl`, `test_store_history`, `test_writer`, `store_fixtures`), `boundaries.toml`, `BOUNDARIES.md` (Projector), `INVARIANTS.md`, flow doc S8, `DEPLOYMENT-CONTRACT.md` and the generator/env example (Neo4j/Qdrant services and keys), and `SOURCE-GOVERNANCE.md`. Task 0c then added a *second*, generic "export sink" path next to it. Run `grep -rniE 'neo4j|qdrant|graphrag'` over `gen2 tools docs/gen2 deploy Makefile` for the full list.

## Target
1. **One outbound path.** Collapse publication and export into a single export surface: a versioned **export API**. That means the finished-research package (start from 0c's `export-bundle`) plus one connector contract that the engine drives identically for every enabled connector. Keep what the reviews already proved for export:
   - approved-revision binding;
   - ordering pair with the four branches (skip / already-applied / conflict / advance);
   - idempotency, tombstones and receipts;
   - `outcome_unknown` + reconciliation;
   - the `export-webhook/1` receiver protocol;
   - the per-member licence rule;
   - three separate facts (a failed export never changes completion);
   - approved corrections are exported too (S8 rule 5).
2. **No product names in the core.** The build ships only generic reference connectors: SQL over a standard connection string, JSONL/file, webhook. Connector types are a closed, reviewed vocabulary. A new database type is a reviewed connector, and any connector (including one for Neo4j/Qdrant) lives outside the core.
3. **The engine never reads research back from any external database.** Internal readers use the local record. Re-scope the freshness envelope to what still has meaning, or remove it; justify either choice against flow doc S8 and the 0c review rulings.
4. **Amend the governing text to match**, each change marked "operator ruling 2026-09-26":
   - flow doc S8 (`~/work/research-loops-public/private/gen2-flow-architecture-20260924.md`);
   - `BOUNDARIES.md`: rename the Projector entry to the export role and fold in the 0c/0c-repair amendment refinements minus anything setup-specific. The operator has now decided, so this *is* the amendment;
   - `INVARIANTS.md` entries that name Neo4j/Qdrant;
   - `EXPORT-SINKS.md`, `DEPLOYMENT-CONTRACT.md` and `SOURCE-GOVERNANCE.md` (remove Neo4j/Qdrant/GraphRAG services and keys; the stack is engine + research gateway + exporter).
   Leave the methodology synthesis alone. Its GraphRAG mentions are research provenance, not build features.
