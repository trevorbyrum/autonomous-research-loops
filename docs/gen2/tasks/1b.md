## Build `gen2/router/`: the single logical writer
One command service over the store (`open_store`), with no model calls anywhere in its decision path. Its operations are named in the design review:

- `claim` (leases with generations, one live lease per (topic, scope))
- `record_observation`
- `commit_outcome`
- `apply_operator_decision`
- `ack_delivery`
- export-outbox commit

Each operation specifies its uniqueness, fencing and atomicity. Don't expose unrestricted snapshots for callers to mutate.

**`commit_outcome` per C-1…C-13:**
- replay-or-reject by operation ID;
- check lease, generation, expected revision and authority capability. Authority derives from capability, never from a caller-supplied role label (Router must-never);
- one short transaction, with no subprocess or network call inside it (C-8);
- the receipt is returned only after commit (C-5);
- a lost reply is recovered by operation ID;
- expensive validation happens outside the transaction and is bound to exact artifact hashes (C-3).

**Boundary checks the store deliberately leaves to the router (store README):**
- validate every JSON document against `gen2/schema/`;
- recompute hash truth (content, spec, manifest, request-fingerprint and payload digests against staged or stored bytes; C-13 canonicalization via `gen2/core/canonical.py`);
- validate timestamps as real instants via `gen2/core/instants.py`;
- run the A10 semantic comparisons that are due before these rows feed accounting. At minimum:
  - a search observation's `result_count` against the captured retrieval events (complete / partial / unknown kept distinct from zero);
  - a screening receipt against its assessment and protocol version;
  - payload digests against staged bytes.

  Say which of the rest you do now and which you defer, with the phase.

## Test discipline (Gate C)
Each rule gets an isolated negative with a bound mutation and a positive control. At minimum:
- **Replay and identity:** replay of a committed operation returns the identical receipt; the same operation ID with different content is refused; a lost reply is recovered.
- **Fencing:** a stale lease/generation is refused; a wrong expected revision is refused; a cross-topic write is refused (RG-5).
- **Authority:** a role label without capability is refused; a producer verifying its own work is refused.
- **Boundary validation:** a hash label that doesn't match the bytes is refused; a schema-invalid document is refused; an impossible timestamp is refused.
- **Atomicity:** a crash (injected fault) mid-transaction leaves no partial state.
- **No write outside the router:** extend the boundary checker so that only `router` may call store write primitives. Prove it by a mutant.

State every structural limit honestly.
