## Required
1. **Encode the ruling in DOSSIER first,** as a closed, versioned validation-method policy.
   - Define what makes an extraction procedure **independent**. At minimum:
     - a different extractor identity (tool or method), not merely a different version of the same extractor;
     - a validator invocation distinct from both the producer and the extracting invocation.
   - Define the success predicate for the method, and the evidence kept for it: the validator's own extraction record and the comparison outcome.
   - Byte agreement between outputs can be established structurally. Any semantic comparison is an attributed verifier assessment; don't claim the store proves it.
   - Same-extractor replay can be recorded as an integrity method whose outcome never satisfies the authorizing predicate.
2. **Durable records,** following the DOSSIER design:
   - an immutable `source_extractions` table, with the complete SQL 14 acquisition key, extractor identity and version, the extracting invocation, a C-9 output artifact, and a supported tier capped by `source_acquisition_content_tiers`;
   - an immutable `extraction_validations` table, with the target extraction, validator invocation, method and policy version, outcome, and a reference to the validator's independent extraction.
   - Use ordered additive DDL with `-- trace:` markers, STRICT tables and foreign keys, refuse every update and delete, and allow no REPLACE path.
   - Add Router admission through a collaborator, keeping `service.py` to wiring only (DEBT-036). Authenticate the artifact outside the writer lock.
3. **Keep every receipt consumer and the SQL 17 fence unchanged** in this part. The records grant no support authority yet.
4. **Tests.**
   - Isolated Router and raw-DDL tests for each guard:
     - a missing or foreign acquisition;
     - a tier above the ceiling;
     - the producer or the extractor validating its own extraction;
     - the same extractor identity presented as independent;
     - a failed outcome;
     - an unauthenticated artifact;
     - immutability;
     - replay/conflict and rollback;
     - accepted controls.
   - Add a predicate-level paired mutant for each guard.
