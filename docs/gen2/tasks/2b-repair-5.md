## F1 — the gateway fact transition rule, enforced on every edge
The late-insert trigger enforces the relation, but an ordinary supersession transaction does not. Update current `C` (revision 3) to point at a not-yet-inserted `N`, then insert `N` as current with revision 2. That commits, and revision 2 becomes current. NULL revisions, a different state at the same onset, and an older episode are also accepted through that path. The router blocks all of these on its typed path; the database does not.

**Required:** a single rule that validates each gateway supersession edge (predecessor → successor), whichever statement created it, checked once the edge is complete. For example, a deferred check or an equivalent commit-time validation over each new edge, rather than one rule per insertion form. Valid edges: the same capability; and either the same episode (`since` and state) with a strictly higher revision, or a later episode, where the revision may reset. Keep the late-snapshot eligibility you already built as an instance of the same relation, not a separate special case, if that falls out naturally. Preserve the graph protections, historical observation links and the new-episode revision reset. Don't impose revision monotonicity across gateway lifetimes; that is Phase 3. Add direct-SQL negatives for each ordinary-successor case in Astra's table (older revision, NULL revision, same onset with a different state, older episode), beside permitted controls for a higher revision and a later episode.

## F2 — one read gate for every persistent-record serving path
Startup refusal works, but `adapters/openalex_snapshot.py` reads `gateway.records.canonical` directly (joined with `gateway.index_docs`) and never checks `restriction_inputs`. An unconverted row written after startup is served through HTTP `/v1/find`, the HTTP MCP door, the stdio MCP bridge, and queued jobs. It is reported as a complete, exhausted `searched_ok` result, and with widened permissions when that row carries a restriction.

**Required:** make "only converted rows are servable" a property of the one place records are read, not of each reader. For example, a single servable-records database view or function that every serving read, including counts, goes through, plus a check (a test or the boundary tooling) that fails if any production code reads `gateway.records` for serving outside it. When a read is refused, counts and coverage must stay honest: a refused row makes the lane partial or degraded, never a complete zero or a silently shorter complete result. Add an assembled-gateway regression: an unconverted indexed row arriving after startup, beside a current-row control, exercised through HTTP, HTTP MCP, stdio MCP and a queued job. Tests only around `Cache.get_record` don't close this. Astra REJECTed `a_row_an_older_gateway_writes_later_is_never_served` as serving-wide evidence; keep it as a narrow test.
