1. **`docs/gen2/DEPLOYMENT-CONTRACT.md`** — the operator-facing deployment specification:
   - Compose stack: engine, federated research gateway, projector; Neo4j/Qdrant/Vault as referenced external services; healthchecks; operator status/MCP transport exposure; port map.
   - Baked-vs-mounted table (engine code/validators/pinned provider CLIs baked; stations.yaml, fleet policy, prompts, approved contracts/evidence/logs, decision thresholds, secrets, agent auth homes mounted). Restart-vs-rebuild rule stated per item.
   - Secrets: env backend (single mounted .env) AND vault backend (address/token-file/mount/prefix/aliases), with the two outage-hardening rules: explicit `RESEARCH_GATEWAY_VAULT_TOKEN_FILE`-style wiring for every service, and failed secrets reads surfacing as dated `secrets backend failing` capability facts (never "no key configured").
   - Custom model CLIs: persistent per-provider auth-home volumes; a mounted `wrappers/` volume that is operator-owned and explicitly operator-trusted (documented as an operator act) — agents can never introduce executables; engine adapters remain image-baked per the adjudicated ruling.
   - Per-job writable workspaces + env allowlists; auth-volume refresh/replacement testing requirement; control-store backup/restore volumes with a documented restore drill.
2. **Generated key catalog + .env.example — one source of truth.** `tools/gen_source_catalog.py` reads the gateway source registry and emits BOTH `docs/gen2/SOURCE-CATALOG.md` (per source: name, what it provides, key-acquisition link, free/paid tier, rate limits, which lanes/domains need it, license/commercial posture) AND `deploy/gen2.env.example` (every secret name, grouped, commented). Drift between registry and either artifact fails `make gen2-check`. Seed content from `gateway/docs/SOURCES.md` — but the registry is authoritative; fix the known gap (semantic-scholar absent from the old env example) by construction.
3. **Export sinks (operator-pluggable research export).** Extend/author schemas: canonical **export bundle** (topic, contract revision, obligations+dispositions+confidence, claim–source links with verification tiers, synthesis views, stopping dossier — versioned, one shape for all sinks) and **ExportSink contract** (deliver(manifest, bundle) → per-sink receipt; idempotent, generation-aware; supersession/tombstones; partial-delivery visible). Specify the three shipped generic adapters — generic SQL (documented relational export schema), JSONL/file, webhook/HTTP — as Phase-3 implementation targets; bespoke sink types are reviewed code. Sink enablement + per-topic export options are mounted config; connection strings live in the secrets surface. The three-facts rule applies: a dead sink is a partial-delivery capability incident, never a block or rewrite of completion.
4. **Source-proposal pathway (agents proposing new research sources).** JSON Schema for a source proposal: what it provides, domain, license/commercial posture, API shape, and placement in the gateway's existing structure (base vs domain lane, family, licensing tier) — plus the governance path: agent proposes → operator approves → adapter lands as a reviewed build task → registry entry → catalog/.env.example regenerate automatically. GraphRAG-side corpus registration (already runtime, no code) documented alongside for contrast.
