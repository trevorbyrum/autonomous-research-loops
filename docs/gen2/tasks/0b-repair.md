## Priority order (matches the review's own ranking)
1. **A1 (HIGH) — transaction lifecycle.** `gen2/store/api.py` `Store.transaction`: the COMMIT call is outside the protected rollback path. Fix: put COMMIT inside the lifecycle such that on failure, roll back if SQLite still reports an active transaction; if the connection can't be recovered, invalidate/close it and surface the failure — never mask the original error with an unconditional rollback after SQLite already ended the transaction. Add a regression using the same deferred-FK relationship the review used (a superseded-capability-fact write with a missing successor), independent-connection read-back showing nothing partial persisted, and a demonstration that a subsequent transaction on the same connection works normally afterward.
2. **A4 (MEDIUM) — unchecked constructor.** `Store.__init__` accepts a raw connection + caller-supplied compatibility dict with no verification. Route production construction through the checked `open_store`/`db.connect` path only. If test fixtures genuinely need direct construction, make that an explicitly separate, clearly-named path — not the same constructor real code uses. Add a test covering both ordinary construction and any adoption route, and update the existing receipt tests that currently use the unchecked constructor.
3. **A2 (HIGH, boundary) — importer TOCTOU races.** `gen2/importer/dry_run.py` (`Gen1Reader.read`, main report creation): path validation and the later file-open are separate operations, so a swap in between defeats containment. Fix needs to bind reads/writes to the *validated filesystem object*, not re-resolve by pathname later — descriptor-relative operations and/or a read-only snapshot of the input tree are the reviewer's suggested directions; evaluate and pick one. Add both race reproductions from the review (output-dir-swapped-to-symlink-into-gen1, source-file-swapped-to-outside-symlink) as regression tests. Note: BOUNDARIES.md's "core-only, no filesystem grant" is an *import* restriction, not a structural filesystem guarantee — don't oversell the fix in prose; describe what it actually prevents.
4. **A3 (HIGH) — managed-store detection via symlink.** The managed-store predicate requires both containment *and* existence; an external symlink to a real managed-store marker makes containment false, so the importer wrongly reports "no managed store" instead of "can't verify." Fix: distinguish "managed-store evidence exists but can't be followed/read" from "there is genuinely no managed store" — report the ambiguous case as a blocking issue (fail closed), never as a clean queue. Test: external-target symlink, dangling/indeterminate entry, ordinary in-root file — three distinct cases, not just the two already covered.
5. **A5 (MEDIUM) — importer input robustness.** Validate input shapes before processing (no uncaught TypeErrors on wrong-typed fields); detect and report duplicate target identities as a named issue rather than silently accepting both; and — the identity-bounds-relevant fix — check numeric identity tokens for exact-integer-ness *before* any lossy float conversion, so a fractional or precision-losing token is reported as an issue rather than silently rounded into a plausible-looking integer. Unknown/unsupported schema versions must be surfaced as an explicit issue, not silently dropped.
