Statistical target recall is refused because no evaluator is implemented, even when a pool and procedure are given.
   - Refuse at **both** boundaries. A contract admitted earlier can't be approved with an unsupported rule, and approval can't add one.
   - First check what `contract-v2.schema.json` already rejects. Close only the remaining gap, in the existing admission/approval path or its collaborator, and don't duplicate the schema.

2. **Contract-to-evaluator binding.**
   - Map each supported rule kind in a contract's stopping profile to its 3a evaluator, with its declared parameters (for example, coverage minimum N and scope; the sentinel inventory reference for known-item).
   - The binding is pure data in `gen2/accounting`; admission validates it.
   - Unknown or unsupported kinds are refused. They are never silently reinterpreted.
3. **Changed-protocol integration fixture, through the Router APIs:**
   - **Incompatible amendment:** evaluate a profile under protocol revision A. Record an incompatible G-1 impact for revision B. The old results and operands aren't reused: affected rules are `unknown` until re-evaluation under B, and re-evaluating with B-current inputs gives the B result.
   - **Compatible amendment (control):** a recorded compatible impact allows reuse.
   - Expected values are written by hand.
4. **Tests.**

   - Binding tests.
