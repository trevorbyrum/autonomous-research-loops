## Goal of this slice
Establish **one** structural pattern and apply it to the two smallest mixins, `Status` and `Capabilities`. Later slices then apply the same reviewed pattern to the larger mixins.

The pattern:
- A mixin becomes an **explicit collaborator** object that the Router composes.
- The collaborator receives the narrow interface it needs from the Router core, as a `typing.Protocol` declared in the collaborator's module, or in a small interface module the core implements.
- The collaborator imports that interface, so the dependency is visible to the import graph and the boundary checker.
- The Router's **public API is unchanged:** it keeps the same public method names, delegating to the collaborators.
- Merging is the alternative when a mixin is really part of one responsibility. Justify whichever you choose.
