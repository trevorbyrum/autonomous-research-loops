# Protected live operands

Host paths come from two operator-set absolute roots, required with no defaults (unset or relative refuses): `GEN2_CONFIG_ROOT` (protected configuration: secrets, bundle, record, manifest, prompts, provider files, buildx config) and `GEN2_DATA_ROOT` (storage: control, spool, staging, outputs, relay-evidence, gateway-db, build-inputs). Export them for `build.py`. The Bake file refuses a missing or relative `GEN2_DATA_ROOT` itself. Compose cannot, so run it only through `build.compose_command`, which enforces both roots; direct Compose invocation is unsupported.

The operator uses `operands.pack` only with the independent verifier's retained record and exact manifest/receipt bytes. Retain all operands; publish no `qualified` record before applicable native witnesses pass (real additionally needs DEBT-004 passed on the verifier's accepted genuine-rejection receipt). A `rejection_experiment` record (DEPLOYMENT-CONTRACT §4.2) is the only record that may carry DEBT-004 pending, and it grants one invocation. Publish regular, single-link files under the protected configuration root, read-only to the engine UID and outside every job/model mount; set the returned byte pin independently of the record. Never put a credential value/hash in these operands. For a real route, pack N10's approved full ID, name, IPv4 CIDR and gateway as `plan.egress_network_id`, `plan.egress_name`, `plan.egress_subnet` and `plan.egress_gateway`. Docker commands use the full ID; the other operands bind the expected readbacks.
Use the explicit `compose.live.yaml` override with the base compose only after provisioning the exact read-only mounts and independent `GEN2_QUALIFICATION_PIN`. Keep the token in its engine-only file and prompts at their pinned module path. Lane B validates the record and owns dispatch authority; changing the record requires a new engine process/epoch, never a reload or resume of old authority. Applying this override, N10, credential use and provider sends remain subject to their separate approvals/readiness gates.

Keep local logging at `max-size=4m`, `max-file=1`, `compress=false` per container, including standalone launchers. Existing containers retain their original logging configuration; replacing one requires its original identity and end checks before a fresh create.
